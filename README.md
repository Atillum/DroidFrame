# DroidFrame

Экран Android-телефона на компьютере: управление мышью, запись видео, скриншоты и сжатие файлов. Раньше приложение называлось Realme Studio. Поддержка не ограничена realme.

## Скачать

Готовые архивы находятся на странице **[Releases](https://github.com/Atillum/DroidFrame/releases)**:

- **DroidFrame-Windows-x64.zip** — Windows 10/11, процессор Intel/AMD x64. Распакуйте **весь** архив в обычную папку и запустите `DroidFrame.exe`. Папка `deps` и файлы рядом с EXE нужны приложению.
- **DroidFrame-macOS-Apple-Silicon.zip** — macOS 13+, Mac с M1 и новее. Распакуйте и откройте `DroidFrame.app`.

ADB, scrcpy, FFmpeg и, на Windows, среда .NET уже включены. Устанавливать Android Studio, Homebrew или .NET отдельно не нужно.

**Windows-версия пока предварительная.** Автоматические проверки не заменяют тест на настоящем Windows-компьютере с телефоном. Архивы пока не подписаны доверенным сертификатом: macOS и Windows могут показать предупреждение при первом запуске. Это не инструкция отключать защиту системы.

## Как пользоваться

1. Включите на телефоне «Для разработчиков» → «Отладка по USB».
2. Подключите телефон кабелем и подтвердите запрос разрешения отладки на его экране.
3. Откройте DroidFrame: подключённый телефон определяется автоматически. Если их несколько, выберите нужный в списке.
4. Нажмите «Начать запись» или «Скриншот». Для сохранения видео нажмите «Стоп и сохранить».

Видео и скриншоты по умолчанию сохраняются в **Рабочий стол → DroidFrame**. Кнопки позволяют выбрать другую папку, открыть текущую или показать последний файл.

Если на Windows телефон не обнаружился, ему может требоваться **ADB-драйвер производителя**. Это зависит от телефона и Windows; наличие драйвера нельзя гарантировать одним приложением. Кабель должен передавать данные, а не только заряжать.

## Возможности

- Экран телефона и кнопки в одном окне; управление мышью и клавиатурой.
- Запись без встроенного трёхминутного ограничения.
- Скриншоты, включая снимки во время записи.
- Качество 720p, 1080p или исходное разрешение.
- Звук телефона, микрофон или запись без звука. Захват аудио требует Android 11+, а отдельные приложения могут запрещать захват своего звука. На Android 11–12 звук телефона может перенаправляться на компьютер.
- Сжатие после записи: H.264, CRF 28, preset fast, AAC 96 кбит/с. Во время обработки виден прогресс; после — имя, папка и размер файла. Результат закрывается крестиком.
- Исходник сохраняется по умолчанию. Его удаление можно включить отдельно; оно происходит только после проверки более компактного результата. При ошибке исходник остаётся.
- Скругление угла Mac-предпросмотра влияет только на окно; видео и скриншоты сохраняются целиком.

Запись выполняет scrcpy. На некоторых Android-оболочках это позволяет записывать экран там, где запись через Android Studio не работает. Mac-версия проверена на realme 14 5G / RMX5070 с Android 16. Это не обещание обхода DRM, защищённых экранов или поддержки всех прошивок.

## Сборка из исходников

В [.github/workflows/build.yml](.github/workflows/build.yml) настроены отдельные Windows- и Mac-сборки. После успешных проверок в `main` создаётся предварительный релиз с ZIP-архивами и SHA-256.

**Windows:** нужен .NET SDK 10 и MSYS2 MINGW64 с GCC, NASM, pkg-config, make, diffutils, curl, tar и openssl. Выполните `scripts/build-windows.ps1`, затем из MINGW64:

```sh
bash scripts/build-ffmpeg.sh windows "$PWD/dist/DroidFrame-Windows-x64/deps/ffmpeg"
```

Проверка готовой Windows-сборки: `DroidFrame.exe --self-test`. Отчёт `self-test-report.json` создаётся рядом с EXE. Проверяются парсер ADB, встраивание окна, кодирование/декодирование, звук, длительность статичного экрана, кириллица в путях, коллизии имён и защита исходника.

**Mac:** нужны Apple Command Line Tools и make (pkg-config необязателен). Выполните `bash scripts/build-macos.sh`. Готовое приложение — `dist/DroidFrame.app`.

FFmpeg и x264 собираются из фиксированных исходников с проверкой SHA-256; их исходные архивы и сценарий сборки включены в приложение. Во время обычной работы загрузок из интернета нет.

## Диагностика

На Windows журнал текущего сеанса: `%LOCALAPPDATA%\DroidFrame\session.log`. Он может содержать серийный номер устройства и пути к файлам: проверьте его перед публичной отправкой. Настройки хранятся рядом в `settings.json`.

Для сообщения о проблеме укажите Windows/macOS, модель телефона, Android, USB или Wi-Fi и действие, после которого возникла ошибка. Не публикуйте личные записи и секреты.
